# (noxcore/src/script/builtins.cpp), in builtin id order. Compiled into noxcore
# (script/builtin_docs.hpp) for the map editor's Script Reference, tooltips and Function Info.
# Written for NoX Core from what our server's script host (= GAME.EXE) does; no text from
# EA's scripts or from other tools' documentation. A test checks that every builtin has an
# entry and that the prototypes agree with the compiler's.
#
# Format. Lines starting with '#' before the first entry are comments.
#   == Name                         starts an entry
#   proto: <type> Name(<type> <param>, ...)   the compiler's types, with parameter names
#   category: <category>            walls timers objects waypoints groups movement creatures
#                                   inventory combat health spells enchants owners sound
#                                   messages dialog quest players triggers math strings game
#                                   unused
#   related: A, B, C                other builtins worth a look
#   short: <one or two sentences>   the tooltip: what it does and what it returns
#   [description]                   what it does (paragraphs; a blank line between them,
#                                   lines starting "- " are bullets)
#   [params]                        "- name: text" for each parameter in order
#   [returns]                       the result (void ones: "Nothing.")
#   [edge]                          bad handles, wrong values, the original's quirks, OB-nnn
#   [example]                       NoxScript, shown as written
# Usage counts come from builtin_usage.txt (generated by builtinUsageReport over the game's maps).

== Wall
proto: object Wall(int column, int row)
category: walls
related: WallOpen, WallClose, WallToggle, WallBreak, WallGroup
short: Looks up the wall at a wall-grid cell (column, row) and returns its handle for the Wall* builtins; 0 when that cell has no wall.
[description]
Turns a wall-grid position into a wall handle. The map's walls sit on a grid of 23-unit cells; the column and row are the cell numbers the editor shows for a wall (a world point divided by 23), not world units.

The handle packs the column and the row together, so the same cell always gives the same handle. Store it in an object variable once (in MapInitialize, say) and pass it to WallOpen, WallClose, WallToggle or WallBreak whenever the wall should change.

In a prefab placed with an offset the cell is moved by the prefab's offset first, so a prefab's script keeps finding its own walls.
[params]
- column: the wall's column on the 23-unit wall grid (its x cell).
- row: the wall's row on the 23-unit wall grid (its y cell).
[returns]
The wall's handle, or 0 when no wall stands in that cell.
[edge]
- A cell without a wall gives 0. Passed on to WallOpen and the like, 0 means cell 0,0 at the map's corner, which is normally empty, so a mistyped cell fails quietly: check the cell numbers in the editor when a wall won't move.
- Only secret walls (walls flagged to open and close) respond to WallOpen, WallClose and WallToggle. WallBreak works on breakable walls.
[example]
object gateWall;

void MapInitialize()
{
    gateWall = Wall(102, 87);
}

void OpenGate()
{
    WallOpen(gateWall);
}

== WallOpen
proto: void WallOpen(object wall)
category: walls
related: Wall, WallClose, WallToggle, WallGroupOpen, NoWallSound
short: Starts a secret wall (a handle from Wall) sliding open; a wall already open or opening is left alone.
[description]
Opens a secret wall: one flagged in the editor to open and close. The wall doesn't vanish at once; it starts opening and the game finishes the slide over the next frames, telling every player's client as it goes.

As it starts, the wall's open sound plays at the middle of its cell: the material's own open sound, or SecretWallOpen when the material has none. NoWallSound(true) silences it (and the close sounds) for the rest of the map.

Ordinary walls don't move. To knock a breakable wall down use WallBreak; to open many walls at once put them in a wall group and use WallGroupOpen.
[params]
- wall: the wall's handle, from Wall(column, row).
[returns]
Nothing.
[edge]
- A handle whose cell has no wall, or a wall that isn't secret: nothing happens.
- A wall already open or opening: nothing happens and no sound plays, so calling it twice is harmless.
- A wall both secret and breakable that has been broken still changes state. In the original game the server then crashes when a player has it in view (OB-122); NoX Core sends nothing. Don't open or close a secret wall that can be broken.
[example]
object vaultWall;

void MapInitialize()
{
    vaultWall = Wall(64, 118);
}

void VaultLeverPulled()
{
    WallOpen(vaultWall);
    PrintToAll("GeneralPrint:SecretFound");
}

== WallGroupOpen
proto: void WallGroupOpen(object group)
category: walls
related: WallGroup, WallOpen, WallGroupClose, WallGroupToggle, WallGroupBreak
short: Starts every secret wall of a wall group (a handle from WallGroup) sliding open, as WallOpen does for one.
[description]
Runs WallOpen on each wall in the group, in the group's order: each secret wall that is shut or shutting starts opening, with its open sound (unless NoWallSound turned wall sounds off). Walls in the group that aren't secret, or are already open, are passed over.

A wall group is made in the editor (select the walls, make a group of them) and found by name with WallGroup. A group of groups works too: each group in it is walked in turn.

This is the usual way to open a long secret passage or a ring of walls with one call: the stock maps call it far more often than WallOpen.
[params]
- group: the wall group's handle, from WallGroup("name").
[returns]
Nothing.
[edge]
- A handle that names no group (0 from a misspelt WallGroup) does nothing.
- An original quirk (OB-138): after its own walls, the walk goes on as if the group were a group of groups, taking each wall's column number as a group id. So the walls of any other wall group whose id equals one of this group's columns open too. NoX Core does the same, but stops where the original would recurse until it crashed.
- Groups of other kinds (objects, waypoints) do nothing here.
[example]
object passage;

void MapInitialize()
{
    passage = WallGroup("HiddenPassage");
}

void OnSwitchOn()
{
    WallGroupOpen(passage);
}

== WallClose
proto: void WallClose(object wall)
category: walls
related: Wall, WallOpen, WallToggle, WallGroupClose, NoWallSound
short: Starts a secret wall (a handle from Wall) sliding shut; a wall already shut or shutting is left alone.
[description]
The opposite of WallOpen. A secret wall that is open or opening starts closing, and the game finishes the slide over the next frames, telling every client.

As it starts, the wall's close sound plays at the middle of its cell: the material's own close sound, or SecretWallClose when it has none. NoWallSound(true) silences it.

Stock maps use it to shut a trap room behind the player, or to close a secret door again some seconds after it opened (with SecondTimer).
[params]
- wall: the wall's handle, from Wall(column, row).
[returns]
Nothing.
[edge]
- A handle whose cell has no wall, or a wall that isn't secret: nothing happens.
- A wall already shut or shutting: nothing happens and no sound plays.
- As with WallOpen, don't use it on a secret wall that can also be broken (OB-122).
[example]
void TrapRoomEntered()
{
    WallClose(Wall(88, 40));
    WallClose(Wall(89, 41));
}

== WallGroupClose
proto: void WallGroupClose(object group)
category: walls
related: WallGroup, WallClose, WallGroupOpen, WallGroupToggle
short: Starts every secret wall of a wall group (a handle from WallGroup) sliding shut, as WallClose does for one.
[description]
Runs WallClose on each wall in the group, in the group's order: each secret wall that is open or opening starts closing, with its close sound (unless NoWallSound turned wall sounds off). Walls that aren't secret, or are already shut, are passed over.

A group of groups works too: each group in it is walked in turn.
[params]
- group: the wall group's handle, from WallGroup("name").
[returns]
Nothing.
[edge]
- A handle that names no group does nothing.
- The original's walk also closes the walls of any wall group whose id equals one of this group's wall columns (OB-138; see WallGroupOpen).
[example]
void ArenaStart()
{
    WallGroupClose(WallGroup("ArenaGates"));
    SecondTimer(60, ArenaOver);
}

void ArenaOver()
{
    WallGroupOpen(WallGroup("ArenaGates"));
}

== WallToggle
proto: void WallToggle(object wall)
category: walls
related: Wall, WallOpen, WallClose, WallGroupToggle
short: Flips a secret wall (a handle from Wall): a shut or shutting wall starts opening, an open or opening one starts closing.
[description]
Reverses whatever the secret wall is doing. A wall that is shut, or on its way shut, starts opening with its open sound; a wall that is open, or on its way open, starts closing with its close sound. Unlike WallOpen and WallClose it always does something to a secret wall, and always plays a sound (unless NoWallSound turned wall sounds off).

Handy for a lever that should open a wall on one pull and shut it on the next. No stock map calls it.
[params]
- wall: the wall's handle, from Wall(column, row).
[returns]
Nothing.
[edge]
- A handle whose cell has no wall, or a wall that isn't secret: nothing happens.
- A wall caught mid-slide turns round from where it is.
- As with WallOpen, don't use it on a secret wall that can also be broken (OB-122).
[example]
void LeverToggled()
{
    WallToggle(Wall(31, 77));
}

== WallGroupToggle
proto: void WallGroupToggle(object group)
category: walls
related: WallGroup, WallToggle, WallGroupOpen, WallGroupClose
short: Flips every secret wall of a wall group (a handle from WallGroup), as WallToggle does for one.
[description]
Runs WallToggle on each wall in the group, in the group's order. Each secret wall is flipped on its own state, so a group whose walls are in different states stays mixed: the open ones close and the shut ones open. Walls that aren't secret are passed over.

That makes it useful for alternating walls (a maze whose walls swap each time a switch is hit). No stock map calls it.
[params]
- group: the wall group's handle, from WallGroup("name").
[returns]
Nothing.
[edge]
- A handle that names no group does nothing.
- The original's walk also flips the walls of any wall group whose id equals one of this group's wall columns (OB-138; see WallGroupOpen).
[example]
void SwapMazeWalls()
{
    WallGroupToggle(WallGroup("MazeSetA"));
    WallGroupToggle(WallGroup("MazeSetB"));
}

== WallBreak
proto: void WallBreak(object wall)
category: walls
related: Wall, WallGroupBreak, WallOpen
short: Destroys a breakable wall (a handle from Wall) as if it had been smashed: sound, burst, debris, and the wall gone for good.
[description]
Breaks a wall flagged as breakable in the editor, exactly as when a player smashes it: the material's break sound (or WallDestroyed) plays at the middle of its cell, a burst effect shows there, and outside quest games 3 to 6 pieces of the material's debris fly out. The wall is then gone for every player, and creatures and missiles pass where it stood.

A broken wall stays broken for the rest of the map; nothing builds it again. A wall raised by the Wall spell falls back to its old shape instead.

NoWallSound doesn't silence the break.
[params]
- wall: the wall's handle, from Wall(column, row).
[returns]
Nothing.
[edge]
- A wall that isn't breakable, one already broken, or a cell without a wall: nothing happens.
- Secret walls are opened with WallOpen, not broken; a wall that is both secret and breakable should not be opened or closed once broken (OB-122).
[example]
void CollapseTunnel()
{
    AudioEvent("EarthRumbleMajor", Waypoint("TunnelWP"));
    WallBreak(Wall(140, 66));
    WallBreak(Wall(141, 67));
}

== WallGroupBreak
proto: void WallGroupBreak(object group)
category: walls
related: WallGroup, WallBreak, WallGroupOpen
short: Destroys every breakable wall of a wall group (a handle from WallGroup), as WallBreak does for one.
[description]
Runs WallBreak on each wall in the group, in the group's order: each breakable wall not yet broken is smashed, with its sound, burst and debris, and is gone for every player. Walls that can't be broken are passed over.

Stock maps use it for cave-ins and for blasting open a row of walls when a puzzle is solved.
[params]
- group: the wall group's handle, from WallGroup("name").
[returns]
Nothing.
[edge]
- A handle that names no group does nothing.
- The original's walk also breaks the walls of any wall group whose id equals one of this group's wall columns (OB-138; see WallGroupOpen).
- Many walls breaking at once each throw their own debris, which can be a lot of objects in a big group.
[example]
void BlastDoorsDown()
{
    WallGroupBreak(WallGroup("RubbleWalls"));
    Effect("JIGGLE", GetWaypointX(Waypoint("BlastWP")), GetWaypointY(Waypoint("BlastWP")), 30.0, 0.0);
}

== SecondTimer
proto: int SecondTimer(int seconds, function callback)
category: timers
related: FrameTimer, SecondTimerWithArg, FrameTimerWithArg, CancelTimer
short: Calls a script function once after the given number of seconds; returns the timer's id (for CancelTimer).
[description]
Starts a one-shot timer. After the given number of seconds (30 game frames each) the server calls the function, with no argument. The timer fires once; to repeat something, have the function start a new timer for itself.

The function runs with no trigger and no caller: self and other name no object inside it. Keep what it needs in a global, or use SecondTimerWithArg to hand it one value.

Timers belong to the map and end with it. A solo game's save keeps the timers still waiting, and they carry on after loading. Timers due on the same frame run oldest first.
[params]
- seconds: how long to wait, in whole seconds (each 30 frames). 0 runs it at the next timer pass.
- callback: the script function to call, by name; it takes no arguments.
[returns]
The new timer's id (1 to 32000, then counting from 1 again); pass it to CancelTimer to stop the timer before it fires.
[edge]
- A negative time is already past, so the timer runs at the next timer pass.
- Waits shorter than a second need FrameTimer.
- The callback's own return value is ignored.
[example]
void OnLeverPulled()
{
    WallOpen(Wall(40, 52));
    SecondTimer(10, CloseAgain);   // shut it again in ten seconds
}

void CloseAgain()
{
    WallClose(Wall(40, 52));
}

== FrameTimer
proto: int FrameTimer(int frames, function callback)
category: timers
related: SecondTimer, FrameTimerWithArg, SecondTimerWithArg, CancelTimer
short: Calls a script function once after the given number of game frames (30 a second); returns the timer's id (for CancelTimer).
[description]
Starts a one-shot timer counted in frames: the game runs 30 frames a second, so FrameTimer(30, F) waits one second and FrameTimer(1, F) runs F on the next frame. It is the most used timer in the stock maps, for short delays, for putting something off to the next frame (letting a pickup or a death finish first), and for loops that run every few frames.

The function is called once, with no argument. To repeat, have it start a new timer for itself; to stop a loop, keep a flag the function checks, or cancel the waiting timer with CancelTimer.

The function runs with no trigger and no caller: self and other name no object inside it. Keep what it needs in a global, or use FrameTimerWithArg to hand it one value. Timers belong to the map and end with it; a solo game's save keeps the ones still waiting. Timers due on the same frame run oldest first.
[params]
- frames: how long to wait, in frames (30 to a second). 0 runs it at the next timer pass.
- callback: the script function to call, by name; it takes no arguments.
[returns]
The new timer's id (1 to 32000, then counting from 1 again); pass it to CancelTimer to stop the timer before it fires.
[edge]
- A negative wait is already past: the timer runs at the next timer pass.
- A timer started from inside a timer's function with a wait of 0 runs in the same pass, straight after.
- The callback must not return a value: a timer function that does leaves it on the script stack and from then on every object handler of the map is put off (OB-204). The editor's lint warns about it.
- A function with parameters given to FrameTimer reads 0 for its first one.
[example]
int spinStep;

void StartSpinner()
{
    spinStep = 0;
    FrameTimer(5, SpinOnce);
}

void SpinOnce()
{
    LookWithAngle(Object("Spinner"), spinStep * 32);
    spinStep = spinStep + 1;
    if (spinStep < 8)
        FrameTimer(5, SpinOnce);   // again in a sixth of a second
}

== Move
proto: void Move(int obj, object waypoint)
category: movement
related: GroupMove, Waypoint, Walk, Wander, GoBackHome, SetCallback
short: Sends a monster walking to a waypoint (then on along its links), or starts the movers that carry an object along a waypoint path.
[description]
What happens depends on the object.

- A monster forgets its current orders and walks to the waypoint, finding its way round walls. If the waypoint has links to others, it then roams on along the waypoint network from there (using the waypoint kinds its roam flags allow, see SetRoamFlag). When it is done, its end-of-waypoint handler (SetCallback event 11, or the one set in the editor) runs.
- A Mover object (placed in the editor to carry something) is switched on and sets off along the waypoint path starting at that waypoint, carrying its load.
- Any other object is moved by the movers carrying it: every Mover whose load is this object sets off from the waypoint. This is how stock maps slide stone blocks and platforms along a path (Move(Object("BlockB2"), Waypoint("B2Home"))).

Objects that are neither monsters nor carried by a mover don't move at all; put them somewhere directly with MoveObject.
[params]
- obj: the monster, mover or carried object (self, other, or an id from Object).
- waypoint: where to go, a waypoint handle from Waypoint("name").
[returns]
Nothing.
[edge]
- A dead monster, a missing object, or a waypoint handle that names no waypoint: nothing happens.
- A mover running along a path exactly level with x or y never sees it passed a waypoint and stops short (OB-031); one at a waypoint whose every link leads back where it came from loops for ever (OB-032). Avoid such paths.
- Movers made by CreateMover carry nothing (OB-197), so Move on them or their object does nothing.
[example]
void GuardAlarm()
{
    int guard = Object("CourtyardGuard");
    Move(guard, Waypoint("AlarmBellWP"));
}

void RaisePlatform()
{
    Move(Object("LiftBlock"), Waypoint("LiftTopWP"));   // its mover carries it up the path
}

== GroupMove
proto: void GroupMove(object group, object waypoint)
category: movement
related: Move, ObjectGroup, Waypoint, GroupWalk, GroupWander
short: Does Move for every member of a group: its monsters walk to the waypoint, its movers (and the movers carrying its objects) set off from it.
[description]
Takes each member of the group in turn and treats it as Move does: monsters forget their orders and walk to the waypoint (roaming on along its links, if any), movers start along the path from it, and objects carried by movers are moved by their movers.

Use an object group (ObjectGroup). Only one stock map calls it, to herd a group of caged monsters to one spot.
[params]
- group: the group's handle, from ObjectGroup("name").
- waypoint: where to go, a waypoint handle from Waypoint("name").
[returns]
Nothing.
[edge]
- A handle naming no group, or a waypoint handle naming no waypoint: nothing happens.
- The members are taken straight from the group's list whatever kind of group it is; give it an object group.
- Dead monsters and objects already deleted are passed over.
[example]
void ReleaseThePack()
{
    UnlockDoor(Object("KennelGate"));
    GroupMove(ObjectGroup("Wolves"), Waypoint("VillageSquareWP"));
}

== LookAtDirection
proto: void LookAtDirection(int unit, int direction)
category: movement
related: GroupLookAtDirection, LookWithAngle, LookAtObject, GetDirection
short: Makes a monster turn to face one of eight compass ways, given as a cell of a 3 x 3 grid (0-8); it then carries on with what it was doing.
[description]
Turns a live monster towards one of the eight ways, named by its cell in a 3 x 3 grid read like a keypad laid over the map:

- 0 up-left, 1 up, 2 up-right
- 3 left, 4 (the middle: right), 5 right
- 6 down-left, 7 down, 8 down-right

Up is towards the top of the map as the editor shows it (smaller y), right towards larger x. The turn is added on top of the monster's current orders, not instead of them: it faces that way, then goes back to what it was doing (a monster standing guard stays put, facing the new way).

Stock maps use it to point a creature somewhere at the start of a scene. For any of the 256 facings use LookWithAngle; to face another object use LookAtObject.
[params]
- unit: the monster (self, other, or an id from Object).
- direction: 0 to 8, the grid cell of the way to face (4 counts as right).
[returns]
Nothing.
[edge]
- Only live monsters turn; players, dead monsters and other objects are left alone (use LookWithAngle for those).
- A direction outside 0-8 does nothing in NoX Core; the original faces by whatever data follows its table (OB-119).
[example]
void GuardTakesPost()
{
    int guard = Object("GateGuard");
    LookAtDirection(guard, 7);   // face down the map, towards the gate
}

== GroupLookAtDirection
proto: void GroupLookAtDirection(object group, int direction)
category: movement
related: LookAtDirection, ObjectGroup, LookWithAngle
short: Makes every live monster in a group turn to face one of eight ways (a 3 x 3 grid cell, 0-8), as LookAtDirection does for one.
[description]
Runs LookAtDirection on each member of the group: 0 up-left, 1 up, 2 up-right, 3 left, 4 and 5 right, 6 down-left, 7 down, 8 down-right. Each live monster turns that way on top of its current orders and then carries on with them; other members are left alone.

No stock map calls it.
[params]
- group: the group's handle, from ObjectGroup("name").
- direction: 0 to 8, the grid cell of the way to face.
[returns]
Nothing.
[edge]
- A handle naming no group, or a direction outside 0-8: nothing happens (OB-119 for the original's out-of-range read).
- The members are taken straight from the group's list whatever kind of group it is; give it an object group.
[example]
void ArchersFaceTheBridge()
{
    GroupLookAtDirection(ObjectGroup("WallArchers"), 1);
}

== ObjectOn
proto: void ObjectOn(int obj)
category: objects
related: ObjectOff, ObjectToggle, ObjectGroupOn, IsObjectOn
short: Turns an object on (enabled), the state the editor's "enabled" box sets: triggers react again, traps and elevators work, movers go on.
[description]
Many map objects only work while they are on. Turned on, a trigger or pressure plate reacts to being touched again, an elevator runs, arrow traps and shooting skulls look for targets, sentry globes sweep their beam, steam pipes blow, periodic floor spikes, trap doors and teleport pentagrams work, a mover goes on along its path, and a fire burns things that touch it again. What "on" does is up to each kind of object; for many (a chair, a sign) it changes nothing.

An elevator that actually changes state plays its "elevator on" sound. Every client is told the new state.

ObjectOn on an object already on does no harm. The stock maps use it constantly: to arm a trap or a trigger when the player reaches a room, and to start machinery.
[params]
- obj: the object (self, other, or an id from Object).
[returns]
Nothing.
[edge]
- A missing or deleted object: nothing happens.
- Turned on, an object joins the next collision pass at once, so a trigger with something already standing on it can fire straight away.
[example]
void PlayerReachedHall()
{
    ObjectOn(Object("HallTrapTrigger"));
    ObjectOn(Object("HallArrowTrap1"));
    ObjectOn(Object("HallArrowTrap2"));
}

== WaypointOn
proto: void WaypointOn(object waypoint)
category: waypoints
related: WaypointOff, WaypointToggle, WaypointGroupOn, IsWaypointOn
short: Turns a waypoint on, so creatures finding their way along the waypoint network (and random teleports) may use it again.
[description]
Waypoints carry an on/off state (the editor's "enabled" box). An off waypoint is skipped by creatures roaming along the waypoint network (Wander, or the roam that follows Move) or planning a long walk across it, and by the random choice of a destination for a teleport to a random place. Turning it on lets them use it again.

Turning a few waypoints on and off is the way to open or close a route for creatures, for instance once a bridge is lowered.
[params]
- waypoint: the waypoint's handle, from Waypoint("name").
[returns]
Nothing.
[edge]
- A handle that names no waypoint: nothing happens.
- Scripts can still use an off waypoint directly: Move, CreateObject, AudioEvent and GetWaypointX don't check its state.
- Movers follow their path's links whatever their state.
[example]
void BridgeLowered()
{
    WaypointOn(Waypoint("BridgeWP1"));
    WaypointOn(Waypoint("BridgeWP2"));
}

== ObjectOff
proto: void ObjectOff(int obj)
category: objects
related: ObjectOn, ObjectToggle, ObjectGroupOff, IsObjectOn
short: Turns an object off (disabled): triggers stop reacting, traps and elevators stop, movers pause, fires stop burning.
[description]
The opposite of ObjectOn. Turned off, a trigger or pressure plate ignores what touches it, an elevator stops, arrow traps and shooting skulls stop shooting, a sentry globe's beam goes out and swings back to where it started, steam pipes, periodic floor spikes, trap doors and teleport pentagrams go still, a mover pauses where it is, and a fire stops burning what touches it. Every client is told the new state.

An elevator that actually changes state plays its "elevator off" sound.

The commonest call in the stock maps is ObjectOff(self) inside a trigger's handler, so the trigger fires only once.
[params]
- obj: the object (self, other, or an id from Object).
[returns]
Nothing.
[edge]
- A missing or deleted object: nothing happens.
- Turning off a creature or a player has no special meaning; use Frozen or the creature builtins to stop a creature.
[example]
void TreasureTriggerStepped()
{
    ObjectOff(self);   // only once
    UnlockDoor(Object("TreasureDoor"));
    PrintToAll("GeneralPrint:SecretFound");
}

== ObjectGroupOff
proto: void ObjectGroupOff(object group)
category: objects
related: ObjectOff, ObjectGroupOn, ObjectGroupToggle, ObjectGroup
short: Turns off (disables) every object of an object group, as ObjectOff does for one.
[description]
Runs ObjectOff on each object in the group, in the group's order. A group of groups works too.

Stock maps use it to disarm a room's traps at once, or to switch off every other trigger of a puzzle when one of them has fired.
[params]
- group: the object group's handle, from ObjectGroup("name").
[returns]

== SecondTimerWithArg
proto: int SecondTimerWithArg(int seconds, int value, function callback)
category: timers
related: SecondTimer, FrameTimerWithArg, FrameTimer, CancelTimer
short: Calls a script function once after the given number of seconds, passing it one value; returns the timer's id (for CancelTimer).
[description]
Like SecondTimer, but the function receives one int when the timer fires: an object's id, an index into an array, a counter. That lets one function serve many timers at once, each with its own value, where a plain timer would need a global per timer.

After the given number of seconds (30 frames each) the server calls the function with the value as its argument. The timer fires once. As with every timer, the function runs with no trigger and no caller: self and other name no object, so pass what it needs as the value.

Timers belong to the map and end with it; a solo game's save keeps the ones still waiting, with their values. No stock map calls this one; they use FrameTimerWithArg.
[params]
- seconds: how long to wait, in whole seconds (each 30 frames). 0 runs it at the next timer pass.
- value: the int handed to the function (an object id, an index, any number).
- callback: the script function to call, by name; it must take exactly one parameter.
[returns]
The new timer's id (1 to 32000, then counting from 1 again); pass it to CancelTimer to stop the timer before it fires.
[edge]
- A function with no parameter never sees the value; one with two or more reads stray stack words for the rest. Give it exactly one int parameter (the editor's lint checks).
- Pass a real id (GetTrigger(), GetCaller(), Object(...)), not self or other: those are stand-ins that mean nothing inside the timer's function.
- An object id passed as the value stays just a number: if the object is deleted meanwhile, builtins given it do nothing.
- A string made at run time (IntToString, a joined string) is freed after the next object handler, so don't pass one as the value (OB-201).
- The callback must not return a value (OB-204).
[example]
void TorchLit()
{
    int torch = GetTrigger();
    SecondTimerWithArg(15, torch, PutOut);   // each torch goes out 15 s after it was lit
}

void PutOut(int torch)
{
    ObjectOff(torch);
}

The wait is in frames (30 to a second). The timer fires once; the function runs with no trigger and no caller, so the value is the way to tell it what to work on. A solo game's save keeps waiting timers with their values.
[params]
- frames: how long to wait, in frames (30 to a second). 0 runs it at the next timer pass.
- value: the int handed to the function (an object id, an index, any number).
- callback: the script function to call, by name; it must take exactly one parameter.
[returns]
The new timer's id (1 to 32000, then counting from 1 again); pass it to CancelTimer to stop the timer before it fires.
[edge]
- A function with no parameter never sees the value; one with two or more reads stray stack words for the rest (the editor's lint checks).
- Pass a real id (GetTrigger(), GetCaller(), Object(...)), not self or other: those are stand-ins that mean nothing inside the timer's function.
- A string made at run time is freed after the next object handler, so don't pass one as the value (OB-201).
- The callback must not return a value (OB-204).
[example]
void PlateOnePressed()
{
    ObjectOff(Object("DartTrap1"));
    FrameTimerWithArg(90, Object("DartTrap1"), ReArm);   // back in three seconds
}

void PlateTwoPressed()
{
    ObjectOff(Object("DartTrap2"));
    FrameTimerWithArg(90, Object("DartTrap2"), ReArm);
}

void ReArm(int trap)
{
    ObjectOn(trap);
}

== Damage
proto: void Damage(int target, int source, int amount, int damageType)
category: health
related: GroupDamage, RestoreHealth, CurrentHealth, Delete, Enchant
short: Hurts an object by an amount of a damage type, through its normal defences; the source (or 0) is who did it.
[description]
Deals damage to a creature, a player or any object with health, as if a blow or a spell had landed: armour and protections lessen it by type, invulnerability stops it, and a target brought to 0 dies as usual (its death handler runs, and the source's player is credited with the kill).

The damage type is a number:
- 0 blade, 1 flame, 2 crush, 3 impale, 4 drain, 5 poison, 6 dispel undead, 7 explosion, 8 bite
- 9 electric, 10 claw, 11 impact, 12 lava, 13 death magic, 14 plasma, 15 mana bomb, 16 zap ray, 17 airborne electric

The source is the object held responsible: its player (or the player owning it) gets the credit for a kill. Stock maps nearly always pass 0 for no source, with type 0 most often and now and then 5 (poison), 9 (electric) or 12 (lava).
[params]
- target: who is hurt (self, other, or an id from Object).
- source: who did it (an object id), or 0 for nobody.
- amount: how much health to take before defences; must be above 0.
- damageType: the damage type number, 0 to 17 (see above).
[returns]
Nothing.
[edge]
- An amount of 0 or less does nothing (use RestoreHealth to heal).
- A missing target: nothing happens. A missing source counts as no source.
- With a source, the target's usual rules about who may hurt it apply: a source on the target's own side may do nothing. Pass 0 to be sure the damage lands.
- An object without health (most scenery) isn't hurt, though it may still react (its hit handler, a sound).
[example]
void CrusherFalls()
{
    Damage(other, 0, 300, 2);   // 300 crush damage, no one to blame
    AudioEvent("BoulderMove", Waypoint("CrusherWP"));
}

proto: void Enchant(int obj, string enchantName, float seconds)

related: GroupEnchant, EnchantOff, HasEnchant, CastSpellObjectObject
short: Puts an enchantment (by name, like "ENCHANT_INVULNERABLE") on an object for some seconds; 0 seconds means for good.
[description]
Gives the object an enchantment at full strength, as a spell would, with that spell's "on" sound. The name is one of:

- ENCHANT_INVISIBLE, ENCHANT_MOONGLOW, ENCHANT_BLINDED, ENCHANT_CONFUSED, ENCHANT_SLOWED, ENCHANT_HELD, ENCHANT_DETECTING, ENCHANT_ETHEREAL
- ENCHANT_RUN, ENCHANT_HASTED, ENCHANT_VILLAIN, ENCHANT_AFRAID, ENCHANT_BURNING, ENCHANT_VAMPIRISM, ENCHANT_ANCHORED, ENCHANT_LIGHT
- ENCHANT_DEATH, ENCHANT_PROTECT_FROM_FIRE, ENCHANT_PROTECT_FROM_POISON, ENCHANT_PROTECT_FROM_MAGIC, ENCHANT_PROTECT_FROM_ELECTRICITY, ENCHANT_INFRAVISION, ENCHANT_SHOCK, ENCHANT_INVULNERABLE
- ENCHANT_TELEKINESIS, ENCHANT_FREEZE, ENCHANT_SHIELD, ENCHANT_REFLECTIVE_SHIELD, ENCHANT_CHARMING, ENCHANT_ANTI_MAGIC, ENCHANT_CROWN, ENCHANT_SNEAK

The time is in seconds and may have a fraction (0.25 is about 7 frames). [params]

- enchantName: the enchantment's name, exactly as listed (case counts).
- seconds: how long it lasts; 0 for good.
[returns]
Nothing.
[edge]
- An unknown name, or a missing object: nothing happens.
- The dead, the destroyed and the frozen (Frozen) get nothing.
- An enchantment already on for good stays for good; a timed one gets the new time, shorter or longer.
- The time is cut to whole frames; a time under one frame counts as 0, for good. Times past about 36 minutes wrap round, and a negative time comes out as a long one: keep it between 0 and a few minutes.
- Some creatures refuse some enchantments: Hecubah anti-magic; outside solo games, fear-proof creatures ENCHANT_AFRAID; in quests, Hecubah and the Necromancer confusion.
- ENCHANT_DEATH kills its holder when it runs out.
[example]

}

{

}

proto: int Object(string name)
category: objects
related: ObjectGroup, Waypoint, WallGroup, CreateObject, GetTrigger
short: Finds a map object by the script name given to it in the editor; returns its id for the other builtins, 0 when none has that name.
[description]
Turns an object's name (set in the editor) into its script id, the int every object builtin takes. It is by far the most called builtin: stock maps look up their doors, levers, creatures and traps with it, usually once into globals in MapInitialize.

- An object deleted this frame may still be found until the frame ends, but builtins given its id do nothing.
- 0 passed on to other builtins makes them do nothing, so a misspelt name fails quietly; the editor warns about literal names nothing on the map has.

{

== MoveObject
proto: void MoveObject(int obj, float x, float y)
category: movement
related: GetObjectX, GetWaypointX, MoveWaypoint, Move, Raise, PushObject
short: Puts an object at a map position (x, y in world units) at once, with no walk and no teleport effect; immobile objects stay put.
[description]
Moves the object straight to the point: no walking, no flash, no sound. It is the stock maps' way of setting up a scene (putting a creature or a prop in place), of moving players for a cutscene, and of pulling an object out of sight or back again.

Everything that goes with being somewhere new happens: the object meets whatever is at the new spot, a creature drops the path it had planned, its pixies follow, and when a creature or player moves every creature looks about afresh next frame. A player's camera goes with them, and their client reloads what it sees.

Inside a prefab's function the prefab's offset is added to x and y, so a prefab's script works in prefab coordinates.
[params]
- obj: the object (self, other, or an id from Object).
- x: the new x in world units (23 to a wall cell).
- y: the new y in world units.
[returns]
Nothing.
[edge]
- A missing object, or an immobile one (fixed scenery placed in the editor), doesn't move.
- Nothing stops it: not walls (it can put a thing inside a wall), not ENCHANT_ANCHORED. Choose the spot with care, usually a waypoint's.
- In a prefab, GetObjectX and GetWaypointX give true map positions while MoveObject adds the offset, so moving something onto another object's spot from a prefab with an offset misses by the offset.
- A player's harpoon on the moved creature lets go.
[example]
void StartCutscene()

proto: void MoveWaypoint(object waypoint, float x, float y)

short: Moves a waypoint to a map position (x, y in world units), so sounds, new objects and walks aimed at it go there.
[description]
Changes where a waypoint is. Stock maps keep a spare waypoint and move it about as a pointer: onto the player or a creature (MoveWaypoint(wp, GetObjectX(GetHost()), GetObjectY(GetHost()))) and then play a sound there with AudioEvent, create something there with CreateObject, or send creatures there with Move.

== PushObjectTo
proto: void PushObjectTo(int unit, float x, float y)
category: movement
related: PushObject, MoveObject, Raise, Walk
short: Gives an object a one-frame shove by the vector (x, y): added straight to the force acting on it this frame.
[description]
Adds (x, y) to the force the physics applies to the object this frame. The vector is not a destination: it is a push, in world units, whose direction and size are the x and y you give. A push of (0, -40) shoves the object up the screen; (25, 25) shoves it down and to the right.

The force lasts one frame: the physics turns it into speed during that frame's movement and then clears it, after which the object's drag slows it again. To keep something moving, push it again every frame (a FrameTimer of 1 that restarts itself), or use MoveObject to place it outright.

The push ignores the object's mass: a light bone and a heavy creature get the same shove. Creatures that are held, frozen or charmed don't respond to forces at all while that lasts.
[params]
- unit: the object to push (self, other, or a script id from Object).
- x: the push along x, in world units (positive is to the right).
- y: the push along y, in world units (positive is down the screen).
[returns]
Nothing.
[edge]
- An unknown object does nothing.
- The prefab offset is not added (it is a vector, not a point).
- Only one stock map (G_Mines) calls it.
[example]
// A gust: shove whoever stepped on the plate towards the east.
void GustPlate()
{
    PushObjectTo(other, 60.0, 0.0);
}

== PushObject
proto: void PushObject(int unit, float strength, float x, float y)
category: movement
related: PushObjectTo, MoveObject, GetObjectX, GetObjectY
short: Shoves an object directly away from the point (x, y) with the given strength (negative pulls it towards the point), for one frame.
[description]
Works out the direction from the point (x, y) to the object, scales it to the given strength and adds that to the force acting on the object this frame. A positive strength pushes the object away from the point; a negative strength pulls it towards the point. The size of the push is the strength, whatever the distance: only the direction comes from the point.

Like PushObjectTo the push lasts one frame and ignores mass: the physics turns it into speed and clears it, and the object's drag slows it afterwards. A big strength (stock maps use 25 to 1000) sends things flying.

Stock maps use it for bouncing a player off a bumper (the point is the bumper's position), knocking creatures back from a spot in a set piece, and with a negative strength to scatter freshly made bones towards a point.
[params]
- unit: the object to push.
- strength: how hard, in world units of force; negative pulls towards the point.
- x: the point's x, in world units.
- y: the point's y, in world units.
[returns]
Nothing.
[edge]
- An unknown object does nothing.
- An object standing exactly on the point gets no direction: its force becomes NaN (not a number), which sends it nowhere sensible. Keep the point off the object.
- In a prefab with an offset the original adds the offset to the direction instead of to the point, so the push goes the wrong way (OB-117, kept). Outside prefabs the offset is 0 and this doesn't matter.
[example]
void BumperHit()
{
    // Bounce the player away from the bumper.
    PushObject(other, 60.0, GetObjectX(self), GetObjectY(self));
    AudioEvent("BallBounce", Waypoint("BumperWP"));
}

== GetLastItem
proto: int GetLastItem(int unit)
category: inventory
related: GetPreviousItem, HasItem, GetHolder, Drop, Pickup
short: Returns the newest item in an object's inventory (the one it got last), or 0 when it carries nothing.
[description]
An inventory is a list with the most recently added item first. GetLastItem returns that first item's script id; GetPreviousItem then steps to the next older one. Together they walk everything an object carries, newest to oldest.

Stock maps walk the host's inventory this way to find, drop or remove particular things (a bow, a quest key) before a set piece.
[params]
- unit: the carrier: a player, a creature, or a container that holds items.
[returns]
The script id of the newest item it carries, or 0 when it carries nothing or the object is unknown.
[edge]
- If you drop or delete the item you are standing on during a walk, take its GetPreviousItem first: once the item has left the inventory GetPreviousItem gives 0 for it.
[example]
// Drop every bow the host is carrying.
void DropBows()
{
    int item = GetLastItem(GetHost());
    int next;
    while (item != 0) {
        next = GetPreviousItem(item);
        if (HasClass(item, "WEAPON") && HasSubclass(item, "BOW"))
            Drop(GetHost(), item);
        item = next;
    }
}

== GetPreviousItem
proto: int GetPreviousItem(int item)
category: inventory
related: GetLastItem, HasItem, GetHolder
short: Returns the item after this one in its holder's inventory (the next older one), or 0 at the end of the list.
[description]
Steps one place along the holder's inventory, from newer to older items. Start with GetLastItem(holder) and call GetPreviousItem on each result until it gives 0 to visit every item the holder carries.
[params]
- item: an item that some object is carrying.
[returns]
The script id of the next older item in the same inventory, or 0 when this was the oldest, when the item isn't carried by anyone, or when it is unknown.
[edge]
- An item lying on the ground has no holder, so it gives 0.
- Removing items while walking: fetch the next one before you drop or delete the current one.
[example]
// Count what a chest holds.
int CountItems(int box)
{
    int n = 0;
    int item = GetLastItem(box);
    while (item != 0) {
        n += 1;
        item = GetPreviousItem(item);
    }
    return n;
}

== Pickup
proto: int Pickup(int taker, int item)
category: inventory
related: Drop, HasItem, GetHolder, CreateObject, Delete
short: Makes a player or creature pick up an item, wherever both are; returns 1 when it was taken, 0 when refused.
[description]
Puts a loose item into the taker's inventory exactly as if the taker had picked it up: the item's own pickup rules apply. Gold goes into the purse and the pile disappears, a potion that would help may be drunk on the spot, food can be eaten at once, and weapons or armour the taker's class may not use can be refused. The item's pickup handler, if the map gave it one, runs with the taker as the caller.

There is no reach check: the item can be anywhere on the map. Stock maps use it to hand the host a quest item or a reward: a named item placed out of sight on the map (Object("MaidenReward")) is given with Pickup(GetHost(), ...) when the player earns it. An item just made with CreateObject works too.

In a solo game, when the player's inventory is full the cheapest thing it may drop (not food, not worn, not a glyph, not a quest item) is dropped nearby first, with the "carrying too much" message.
[params]
- taker: who takes it: a player or a creature able to carry things.
- item: the item to take; it must be lying loose (not already carried).
[returns]
1 when the item was taken (or used up by its pickup, like gold), 0 when refused or when either object is unknown.
[edge]
- An item already in someone's inventory, even the taker's own, gives 0: Drop it first.
- A dead taker, or one that can't carry anything, gives 0.
- In a solo game the original tests the taker's type, not the item's, for gold, so giving gold to a player with a full pack still drops its cheapest item (OB-135, kept).
- The item's pickup handler set off while the script is mid-way may be put off until the next handler call (OB-202).
[example]
void RewardHero()
{
    int key = CreateObject("SilverKey", Waypoint("ChestWP"));
    if (!Pickup(GetHost(), key))
        PrintToAll("GeneralPrint:GainedKey");
}

== Drop

short: Makes the holder drop an item it carries onto a clear spot within 50 units of it; returns 1 when dropped, else 0.
[description]
Takes the item out of the holder's inventory and puts it on the ground at a free spot near the holder (within 50 units), running the item's own drop rules: a weapon or armour plays its drop sound, a trap or glyph is laid as the dropper's own, and so on.

Stock maps use it with GetLastItem / GetPreviousItem to take particular things off the player before a scene, or to make a creature drop what it carries.
[params]

== Effect
proto: void Effect(string effectName, float x1, float y1, float x2, float y2)
category: game
related: AudioEvent, CastSpellLocationLocation, GetObjectX, GetWaypointX
short: Shows a visual effect (sparks, explosion, smoke, a lightning ray, a screen shake...) at a point or between two points. Nothing happens in the game itself.
[description]
Sends a purely visual effect to every client. The name is one of the game's effect names (case doesn't matter). What the four numbers mean depends on the kind:
- At the point (x1, y1), x2 and y2 ignored: BLUE_SPARKS, YELLOW_SPARKS, CYAN_SPARKS, VIOLET_SPARKS, EXPLOSION, LESSER_EXPLOSION, COUNTERSPELL_EXPLOSION, THIN_EXPLOSION, TELEPORT, SMOKE_BLAST, DAMAGE_POOF, RICOCHET, WHITE_FLASH.

- JIGGLE: shakes the screen of every player whose view is within 300 units of (x1, y1), weaker farther away; x2 is the strength (stock maps use 10), y2 ignored.

- y2: the ray's end y; otherwise unused.

Nothing.

    Delete(d);
}

== SetOwner
proto: void SetOwner(int owner, int unit)
category: owners
related: ClearOwner, IsOwnedBy, GroupSetOwner, SetOwners, BecomePet, MakeFriendly
short: Makes one object (the first argument) the owner of another: an owned creature or trap is on its owner's side.
[description]
Gives the unit an owner. Ownership decides sides: an object and everything owned by it (or by its owner, up the chain) are on the same side, so a creature owned by the host won't fight the host or the host's other creatures, and fights the host's enemies. Harm done by an owned object (a trap, a missile) is traced back to its owner.

Note the order: the owner comes first, the unit second. Stock maps use SetOwner(GetHost(), creature) to put a creature on the player's side, and SetOwner(somebody, trap) so a trap's damage counts as that somebody's.

The unit leaves its old owner first. If it was a creature a player controlled (a summon or a pet), that player loses it. An owner that is being deleted passes the unit on to its own owner.
[params]
- owner: the new owner.
- unit: the object that gets the owner.
[returns]
Nothing.
[edge]
- An unknown unit: nothing. An unknown owner (or 0): the unit is left with no owner, as ClearOwner.
- Owning a creature doesn't make it follow anyone: use BecomePet or CreatureFollow for that.
- An owned creature forgets the enemy it was after.
[example]
void FreedPrisoner()
{
    int p = Object("Prisoner");
    SetOwner(GetHost(), p);
    CreatureFollow(p, GetHost());
}

== SetQuestStatus
proto: void SetQuestStatus(int value, string name)
category: quest
related: GetQuestStatus, SetQuestStatusFloat, GetQuestStatusFloat, ResetQuestStatus
short: Stores a whole number under a name that lasts beyond this map: later maps of the campaign can read it with GetQuestStatus.
[description]
Quest variables are the campaign's memory. They belong to the game, not the map: they stay when the player moves on to another map, and a solo game's save keeps them. Note the order: the value comes first, then the name.

A name without a colon is the current map's: "BeatMine" set in Con03B is stored as "Con03B:BeatMine". Another map reads it with the full name, GetQuestStatus("Con03B:BeatMine"). Names are matched ignoring case.

Setting a variable that exists replaces its value; otherwise a new one is made. Stock maps store flags (1) for story events: a gauntlet entered, a character killed, prisoners saved.
[params]
- value: the number to store.
- name: the variable's name, "Name" for this map's or "Map:Name" for any.
[returns]
Nothing.
[edge]
- Writing a name that already holds a float (from SetQuestStatusFloat) stores your int's bits, and the variable stays marked a float.
- In the original the quest variables' records hold 132 characters; a longer full name overruns them (OB-216). NoX Core keeps any length.
[example]
void PrisonersFreed()
{
    SetQuestStatus(1, "PrisonersFreed");    // stored as "<ThisMap>:PrisonersFreed"
}

[description]

== ResetQuestStatus
proto: void ResetQuestStatus(string name)
category: quest
related: SetQuestStatus, GetQuestStatus, SetQuestStatusFloat
short: Deletes a quest variable, or several with a '*' wildcard ("*:*" clears them all).
[description]
Removes quest variables so they read 0 again. The name is scoped as for SetQuestStatus (no colon: this map's). Then:
- No '*': removes that one variable.
- "*:*": removes every quest variable of the game.
- A '*' at the end, "Map:Prefix*": removes every variable whose name starts with that text (case ignored). "Con03B:*" clears all of Con03B's, and "*" alone clears the current map's.
- A '*' at the start, "*Suffix": removes every variable whose name ends with that text.

No stock map uses it.
[params]
- name: the variable's name or a pattern with '*'.
[returns]
Nothing.
[edge]
- A '*' anywhere else works only right after the colon ("Map:*Suffix"); in the middle of a name ("Map:Door*Open") it removes nothing. These are the original's rules, kept (OB-216).
- With "*Suffix" the text is looked for at its first appearance in the name (case counts there): a name that has it earlier as well as at its end is missed (OB-216).
[example]
void RestartTrials()
{
    ResetQuestStatus("Trial*");     // this map's Trial1, Trial2, ...
}

== SetDialog
proto: void SetDialog(int npc, string dialogType, function start, function end)
category: dialog
related: TellStory, StoryPic, StartDialog, CancelDialog, GetAnswer, IsTalking
short: Makes a creature (an NPC) someone players can talk to: names the function run when a conversation starts, the one run when it ends, and the dialog's buttons.
[description]
Gives an NPC a conversation. Clients then show it as one to talk to, and a player clicking it (or the script's StartDialog) runs the start function. In both functions self is the NPC and other is the player.
- The start function shows the NPC's line, normally with TellStory. The player's screen opens the dialog window and the player is frozen until answering.
- When the player answers, the window closes, the player is free again and the end function runs. GetAnswer(self) there says what was clicked.

The dialog type picks the buttons, by name (case counts):
- "NORMAL": a Done button.
- "NEXT": a Next button (for a line that continues).
- "YESNO": Yes and No; GetAnswer gives 1 for Yes, 2 for No (0 for Done/Escape).
- "YESNONEXT": Yes, No and Next.

It is how every campaign conversation works: stock maps call SetDialog again inside an end function to move the NPC on to its next line or its next topic, and point the start at an empty function (with TellStory nowhere) when the NPC should say nothing more.
[params]
- npc: the creature to talk to (a monster or NPC object).
- dialogType: "NORMAL", "NEXT", "YESNO" or "YESNONEXT".
- start: the script function run when a conversation begins (no arguments).
- end: the script function run when the player answers (no arguments).
[returns]
Nothing.
[edge]
- Only creatures can have a dialog; other objects (and unknown ones) are ignored.
- An unknown type name counts as "NORMAL" (some stock maps pass "FALSE", which is just that).
- A YESNONEXT dialog's answer is always 0 (OB-128, kept): use YESNO when you need the answer.
- The start and end functions must not return a value: a returned value left behind stops every later handler of the map (OB-204).
[example]
void MapInitialize()
{
    int smith = Object("Smith");
    StoryPic(smith, "MalePic5");
    SetDialog(smith, "YESNO", SmithStart, SmithEnd);
}

void SmithStart()
{
    LookAtObject(self, other);
    TellStory("SwordsmanHurt", "Con02a:ConManSalesPitch");
}

void SmithEnd()
{
    if (GetAnswer(self) == 1) {
        ChangeGold(other, -50);
        Pickup(other, CreateObject("Longsword", Waypoint("SmithWP")));
    }
}

== CastSpellObjectObject
proto: void CastSpellObjectObject(string spellName, int caster, int target)
category: spells
related: CastSpellObjectLocation, CastSpellLocationObject, CastSpellLocationLocation, AwardSpell, Enchant
short: Makes an object cast a spell (such as "SPELL_FIREBALL") at another object, free of mana and of any check that it knows the spell.
[description]
The caster turns to face the target and casts the spell at it, as if it had cast it itself: missiles fly from the caster, the spell's sounds and effects play, damage counts as the caster's. No mana is spent and the caster needn't know the spell; any object can be the caster.

The spell's power (1 to 5) is the caster's own: a player's level in that spell (at least 1), a creature's spell power, otherwise 3; in the versus modes (arena, capture the flag, flagball, king of the realm, elimination) it is always 3. [params]
- spellName: the spell's name, e.g. "SPELL_FIREBALL" (upper case, with SPELL_).
- caster: who casts it.
- target: whom it is cast at.
[returns]
Nothing.
[edge]
- An unknown spell name does nothing: the "SPELL_" prefix is required and case counts.
- A dead or destroyed caster, an unknown caster or an unknown target: nothing happens.
- The caster's turn is only for the cast: a creature turns back to its own facing afterwards.
- In the original, a lasting spell cast this way from a generator's onHurt handler can corrupt the list of lasting spells (OB-005); NoX Core handles it safely.
[example]
void GargoyleWakes()

    FrameTimer(45, GargoyleWakes);   // and again in 1.5 s
}

== WideScreen

[description]

== CreatureGuard
proto: void CreatureGuard(int unit, float x, float y, float toX, float toY, float sight)
category: creatures
related: CreatureGroupGuard, CreatureIdle, CreatureHunt, Walk, AggressionLevel, LookAtObject
short: Orders a creature to guard the spot (x, y), facing towards (toX, toY), defending within the given sight distance.
[description]
Clears what the creature was doing and sets it to guard a post. It walks to (x, y) if it is not there, and stands facing the direction from (x, y) towards (toX, toY). Every half second or so it checks its post again: more than 8 units off and not under attack, it walks back; on it, it faces its way, or looks at an enemy or player it sees.

The sight distance replaces the creature's own (the one set in the editor). How it is used depends on the creature's aggression (AggressionLevel):
- Above 0.66: it attacks any enemy it notices, then comes back.
- 0.33 to 0.66 (defending): it fights an enemy that comes within the sight distance of its post, and keeps fighting while it is attacked or the enemy stays within 1.5 times that distance of the post.
- Lower: it doesn't go after enemies from its post.

Stock maps use it two ways. With a waypoint and a sight of 150 to 500, it posts a guard at a door or a bridge.

- unit: the creature to post.
- x: the post's x, in world units.
- y: the post's y.
- toX: x of a point to face (only the direction from the post counts).
- toY: y of the point to face.
- sight: the guard distance, in world units.
[returns]
Nothing.
[edge]
- Only live creatures respond; players, other objects and unknown objects are ignored.
- The facing point should differ from the post; the same point gives no real direction.
- The prefab offset is not added to the points.
[example]
void PostBridgeGuard()
{

    object road = Waypoint("BridgeRoad");

== AggressionLevel
proto: void AggressionLevel(int unit, float level)
category: creatures
related: GroupAggressionLevel, RetreatLevel, CreatureIdle, CreatureHunt, Attack
short: Sets how readily a creature fights: 0.83 attacks any enemy it sees, 0.5 defends itself and its post, 0.16 or 0 stays out of fights.
[description]
Sets the creature's aggression, the number the creature AI checks to decide whether to start a fight. The AI uses three thresholds:
- Above 0.66: it attacks at will. Idle, walking, roaming, following or guarding, it goes for any enemy it sees, and chases noises.
- From 0.33 to 0.66: it defends. Idle, it fights an enemy it sees; walking or following it only fights back when hit; guarding it fights enemies that come near its post.

- unit: the creature (self, other, or a script id from Object).
- level: the aggression, usually 0.0 to 1.0.
[returns]
Nothing.
[edge]
- Works on creatures only; players, other objects and unknown objects are ignored. It works on a dead creature too (for when it is raised again).
- Who counts as an enemy is not changed by this: a creature with a high aggression still leaves its friends alone. See IsAttackedBy.
- CreatureHunt sets the aggression to 0.83 itself.
[example]
void ThiefCaught()
{
    int thief = Object("MarketThief");
    AggressionLevel(thief, 0.83);
    Attack(thief, GetHost());
}

== SetRoamFlag
proto: void SetRoamFlag(int unit, int flags)

short: Sets which waypoint links a creature may roam along: a creature roams only over waypoints whose link flags share a bit with these flags.
[description]
Sets the creature's roam flags, a set of eight bits (1, 2, 4 ... 128). - flags: the roam flags; only the low 8 bits count.
[returns]
Nothing.
[edge]
- Works on creatures only (live or dead); players, other objects and unknown objects are ignored.
- 0 matches no waypoint at all: the creature finds nowhere to roam.
- Values above 255 are cut to their low 8 bits.
[example]
void SendOnPatrol()

The type says how the entry is shown:
- 1: a plain note, in white.
- 2: a quest, in red, after the word for "Quest".
- 4: a completed quest, in grey, after the word for "Completed".
- 8: a hint, in yellow, after the word for "Hint".
Any other value shows in green with no label.

Given one player, the journal sound (JournalEntryAdd) plays at the player for types 1, 2 and 8, not for 4. Given 0, every player in the game gets the entry, without the sound.

Stock maps add quests with type 2 for the host and tell the player with a message, JournalEntry(GetHost(), "...", 2) then PrintToAll("Con01a:NewJournalEntry"); later JournalEdit turns the quest to 4 when it is done. Hints use 8.
[params]
- player: the player's unit (GetHost(), other...), or 0 for every player.
- entryName: the entry's name: its text's key in the string table's Journal section, without the "Journal:" part.
- type: 1 note, 2 quest, 4 completed, 8 hint.
[returns]
Nothing.
[edge]
- Names longer than 63 letters are cut to 63.
- Adding the same name twice gives two entries; nothing checks for a duplicate.
- A name missing from the string table shows as the game's "missing text" placeholder. Custom maps can only use journal keys the game's string table already has.
- An object that isn't a player gets no entry, but the sound still plays at it. In the original game such an object is treated as a player and memory is written that shouldn't be (OB-132): pass only players or 0.
- The journal is part of the player's saved character in a solo game. StartupScreen (a new chapter) removes the host's quest, completed and hint entries; plain notes stay.
[example]
void TalkedToMiner()
{
    JournalEntry(GetHost(), "LocateMineForeman", 2);
    PrintToAll("Con01a:NewJournalEntry");
}

== RetreatLevel
proto: void RetreatLevel(int unit, float level)
category: creatures
related: GroupRetreatLevel, ResumeLevel, AggressionLevel, SetCallback
short: Sets the health fraction (0 to 1) at or below which a creature breaks off and retreats; 0 makes it fight to the death.
[description]
Sets the creature's retreat level, a fraction of its full health. Whenever its health falls to that fraction or below (and it can move and isn't cornered), the creature drops its attacks and retreats: its retreat sound plays and its retreat handler runs (SetCallback event 8). While retreating it flees from any enemy it sees, a few seconds at a time; with no enemy about it looks for food to eat, or wanders. A creature's levels start as its kind's (from the game's creature data), unless the map sets them. Stock maps use RetreatLevel(unit, 0.0) so that bosses and set-piece creatures never run away.
[params]

- level: the health fraction, 0.0 to 1.0 (0.25 retreats at a quarter of full health).
[returns]
Nothing.
[edge]
- Works on creatures only (live or dead); players, other objects and unknown objects are ignored.
- 0.0 means never (a creature at 0 health is dead); 1.0 makes a creature retreat as soon as it is scratched.
- A spellcaster under anti-magic also retreats, whatever its health.
[example]
void BossAwakens()
{
    int boss = Object("CryptLord");

    AggressionLevel(boss, 0.83);

== RunAway
proto: void RunAway(int unit, int from, int frames)
category: creatures
related: GroupRunAway, PauseObject, RetreatLevel, SetCallback
short: Makes a creature run away from an object for the given number of frames (30 a second), then go back to what it was doing.
[description]
Puts a flight on top of the creature's current orders, without clearing them. The creature runs (at its running speed) along a path leading away from the point where the "from" object stands when the order is given; if it has an enemy in sight, it flees from that enemy instead, wherever the enemy goes. The path is worked out afresh every couple of seconds, and sooner when the enemy closes in.

After the given number of frames the flight ends: the creature's end-of-waypoint handler runs (the map's, or one set with SetCallback event 11) and it takes up its old orders again.

Stock maps use it for timid creatures: in a hit handler, RunAway(self, other, 120) sends a creature the player struck scurrying off for four seconds; RunAway(self, GetHost(), 60) makes one shy away from the player for two.
[params]
- unit: the creature that flees.
- from: the object to flee from; only its position at the time of the call counts.
- frames: how long to flee, in frames (30 a second).
[returns]
Nothing.
[edge]
- Only live creatures respond; players, other objects and unknown objects are ignored, as is an unknown "from".
- A creature that is already fleeing ignores the order.
- A creature that can't move, or finds no way out (cornered), stays where it is until the time is up.
- 0 or a negative time ends the flight at once, and the handler runs.
[example]
void RabbitHit()
{
    if (IsCaller(GetHost()))
        RunAway(self, other, 90);   // three seconds
}

== PauseObject
proto: void PauseObject(int unit, int frames)
category: creatures
related: GroupPauseObject, CreatureIdle, Walk, Move, SetCallback
short: Makes a creature stand still for the given number of frames (30 a second), then carry on with what it was doing.
[description]
Puts a wait on top of the creature's current orders, without clearing them. The creature stands where it is for the given number of frames; then its end-of-waypoint handler runs (the map's, or one set with SetCallback event 11) and it resumes its old orders: a walk goes on, a guard returns to its post.

While waiting it doesn't start fights or walk, but its other reflexes still work: blocking a missile, retreating when badly hurt or fleeing can end the pause early.

Stock maps use it for short beats in set pieces and patrols, from half a second to a few seconds (15 to 75 frames): a guard that stops for a moment on its rounds, or an NPC that waits before it speaks.
[params]

- frames: how long, in frames (30 a second).

- 0 or a negative time ends the pause at once, and the handler runs.
[example]
void ButlerAtDoor()

== IsAttackedBy
proto: int IsAttackedBy(int unit, int other)
category: combat
related: Attack, AggressionLevel, IsOwnedBy, HasClass
short: Returns 1 when the first object counts the second as an enemy (the game's hostility test), otherwise 0. Despite the name, nobody needs to be attacking.
[description]
Runs the game's own enemy test, the one creatures use to decide whom to fight and blows use to decide whom to hurt. It does not look at whether anything is actually attacking: it asks whether the two are on opposing sides. Roughly:
- An object is never its own enemy, and objects with the same top owner (followers, summoned creatures, a player's missiles) are never enemies.
- Objects on the same team are never enemies.
- Shopkeepers are nobody's enemy, and anything charmed is nobody's enemy while the charm lasts. Female NPCs are never players' enemies. An observing player is nobody's enemy.
- Two creatures with no team and no player above them are on the same side.
- Otherwise (a player and a monster, a player and a monster generator, two players on no team or different teams) they are enemies.
A few creatures have their own rules: fish, frogs and rats count every other kind as an enemy, nothing counts a fish as one, and a mimic disguised as a chest is nobody's enemy.

Stock maps use it in hit and collision handlers to tell a real threat from a friend: IsAttackedBy(other, GetHost()) checks that what hit the creature is hostile to the player, so that a friendly NPC bumping into it doesn't trigger the trap.
[params]
- unit: the first object.
- other: the second object.
[returns]
1 when unit counts other as an enemy, else 0 (also when either object is unknown).
[edge]
- The test is not exactly symmetric: a few rules (the disguised mimic, the observing player, fish) look only at the second object, so keep the order stock maps use when it matters.
[example]
void TripwireTouched()
{
    if (IsAttackedBy(other, GetHost()))
        return;              // monsters don't set it off
    ObjectOn(Object("AlarmBell"));
}

== HasSubclass
proto: int HasSubclass(int unit, string subclassName)
category: objects
related: HasClass, HasItem, GetLastItem, IsSummoned
short: Returns 1 when the object has the named subclass flag (such as "BOW", "HEALTH_POTION", "SMALL_MONSTER"), otherwise 0. Pair it with HasClass.
[description]
Objects have, besides their classes (HasClass), a set of subclass flags whose meaning depends on the class: an armour's says which piece it is, a weapon's what kind of weapon, a creature's its size and nature. HasSubclass looks the name up in the game's subclass lists and tests that flag on the object. The lists, searched in this order:
- Armour: HELMET, SHIELD, BREASTPLATE, ARM_ARMOR, PANTS, BOOTS, SHIRT, LEG_ARMOR, BACK.
- Weapons: FLAG, QUIVER, BOW, CROSSBOW, ARROW, BOLT, CHAKRAM, SHURIKEN, SWORD, LONG_SWORD, GREAT_SWORD, MACE, AXE, OGRE_AXE, HAMMER, STAFF, and the staff kinds (STAFF_LIGHTNING, STAFF_FIREBALL, STAFF_DEATH_RAY, STAFF_OBLIVION_ORB...).
- Creatures: SMALL_MONSTER, MEDIUM_MONSTER, LARGE_MONSTER, SHOPKEEPER, NPC, FEMALE_NPC, UNDEAD, MONITOR, MIGRATE, IMMUNE_POISON, IMMUNE_FIRE, IMMUNE_ELECTRICITY, IMMUNE_FEAR, BOMBER, NO_TARGET, NO_SPELL_TARGET, HAS_SOUL, WARCRY_STUN, LOOK_AROUND, WOUNDED_NPC.
- Food: SIMPLE, APPLE, JUG, POTION, HEALTH_POTION, MANA_POTION, CURE_POISON_POTION, MUSHROOM, HASTE_POTION, and the other potions.
- Others: HEAVY, LAVA, GATE, VISIBLE_OBELISK, INVISIBLE_OBELISK, TECH, LOTD, USEABLE, CHEST_NW (NE, SE, SW), STONE_DOOR; books: SPELL_BOOK, FIELD_GUIDE, ABILITY_BOOK; missiles: MISSILE_COUNTERSPELL, MAGIC; generators: GENERATOR_NW (NE, SE, SW); exits: QUEST_EXIT, QUEST_WARP_EXIT.

The flag tested is the name's place in its list, whatever the object's class, so the same flag means different things for different classes ("SHIELD" and "MEDIUM_MONSTER" are the same flag). Always check the class first, as stock maps do: HasClass(item, "FOOD") && HasSubclass(item, "HEALTH_POTION"), or HasClass(item, "WEAPON") && HasSubclass(item, "BOW").
[params]
- unit: the object to test.
- subclassName: the subclass name, in capitals, exactly as listed.
[returns]
1 when the object has that flag, 0 when it doesn't or the object is unknown. For a name in none of the lists, nothing at all (see below).
[edge]
- A name in none of the lists (a typo, or lower case) returns no value, which throws the script's stack off for the rest of that function; in the original game it reads on through memory past the lists and may crash (OB-118). Use only the listed names.
- The flag means something different for each class: on a creature, HasSubclass(unit, "SHIELD") really tests MEDIUM_MONSTER.
[example]
// Count the health potions the host carries.
int CountHealthPotions()
{
    int n = 0;
    int item = GetLastItem(GetHost());
    while (item != 0) {
        if (HasClass(item, "FOOD") && HasSubclass(item, "HEALTH_POTION"))
            n += 1;
        item = GetPreviousItem(item);
    }
    return n;
}

== AutoSave
proto: void AutoSave()
category: game
related: StartupScreen, DeathScreen, GetHost
short: In a solo game, saves the game to the AutoSave slot at the end of the frame, as soon as the player is free to act. Does nothing in multiplayer.
[description]
Asks for a save of the solo game under the name AUTOSAVE, the slot the game's load menu shows as the AutoSave. The save is made at the end of the current frame, once the player is able to act: alive, not frozen, not in a conversation, and no award flying from the book to the spell bar. Until then the request waits, and the save happens the first frame the player is free.

Just before saving, the map's MapShutdown function runs (it runs before every save, not only when leaving the map), and the save then records the map and the player as they are.

Stock maps (Con05A, War05A, War07E, Wiz05A, Wiz07B, Wiz07C) call it at checkpoints in long levels: after a hard fight, before a boss, or as the player passes a point of no return, from a trigger the player walks over.
[params]
[returns]
Nothing.
[edge]
- Only a solo game saves; in any other game the call does nothing.
- Asked for while the player is dead, the save waits; it is not made unless the player is alive again.
- Put the call in a trigger that fires once (or guard it with a variable): every call saves again.
- Keep MapShutdown free of anything that should only happen when the map really ends, since an AutoSave runs it too.
[example]
int checkpointSaved = 0;

void CheckpointPlate()
{
    if (checkpointSaved == 0 && IsCaller(GetHost())) {
        checkpointSaved = 1;
        AutoSave();
    }
}

== Music
proto: void Music(int track, int volume)
category: sound
related: MusicEvent, MusicPushEvent, MusicPopEvent, AudioEvent
short: Plays a music track by its number (0 for silence) at a volume of 0 to 100, for every player; the track loops until changed.
[description]
Changes the music. In a solo game the host's own music changes; in other games every client is told. The old track fades out and the new one fades in over about a second; a track that ends starts over, so music loops until something else is asked for. The players' own music volume setting scales it.

The tracks, by number:
- 0: silence.
- 1 chap1, 2 chap2wiz, 3 chap2con, 4 chap2war, 5 chap3, 6 chap4, 7 chap5, 8 chap6, 9 chap7, 10 chap8, 11 chap9, 12 chapa, 13 chapb: the chapter themes.
- 14 title, 15 town1, 16 town2, 17 town3: the title and town themes.
- 18 sub1, 19 sub2, 20 sub3: dungeon moods.
- 21 wander1, 22 wander2, 23 wander3, 29 wander4: exploring.
- 24 credits, 25 shell (the menus).
- 26 action1, 27 action2, 28 action3: fights.

Stock maps set the level's music in MapInitialize or MapEntry, switch to an action track when a fight starts and back when it ends, and use Music(0, 100) for silence before a scene. The most used tracks are 18 (sub1) and the three action themes. Nearly every call passes a volume of 100.
[params]
- track: the track number, 0 to 29 (0 is silence).
- volume: the track's volume, 0 to 100.
[returns]
Nothing.
[edge]
- Asking for the track that is already playing leaves it playing where it is, at the volume it started with: Music can't change the volume of the current track.
- A number above 29 has no track: it plays silence. Volumes above 100 count as 100. Over the network both numbers travel as bytes (0 to 255).
- The music files come from the game's music folder; a missing file plays silence.

== GetTrigger
proto: int GetTrigger()
category: triggers
related: GetCaller, IsTrigger, IsCaller
short: Returns the script id of the object this call is about (what self stands for here), or 0 when there is none.
[description]
self is not an object id: it is a placeholder (-2) that every builtin reads as "this call's trigger". Stored in a variable it keeps that meaning, so a timer that reads it later finds no object at all (timers have no trigger). GetTrigger turns the trigger into its real script id, which can be stored, compared and passed on like any value from Object.

Use it whenever a handler wants to remember which object fired it: one shared function used by many identical objects (stock maps share one handler among several wisps and look up which one ran), or a handler that starts a timer that must act on the same object later.
[params]
[returns]
The trigger's script id, or 0 when the call has no trigger (a timer, MapInitialize and the other entry points).
[edge]
- Inside a timer's function it returns 0, like self names nothing there.
- self and GetTrigger() name the same object; only GetTrigger's value survives being stored.
[example]
int lastLamp;

void LampTouched()
{
    lastLamp = GetTrigger();       // remember which lamp ran this
    FrameTimer(30, LampOff);
}

void LampOff()
{
    ObjectOff(lastLamp);           // 'self' would name nothing here
}

The cutscene lock. A frozen object stops updating: it doesn't move or act on its own until it is thawed. == SetCallback
proto: void SetCallback(int monster, int event, function callback)
category: creatures
related: Damage, CreatureIdle, Move, GetCaller, GetTrigger
short: Sets which script function a monster runs on one of its events (3 enemy seen, 5 death, 7 hit, 11 end of waypoint...), replacing the map's.
[description]
Monsters have script handlers for their events, which the map editor can set. SetCallback replaces one of them from the script. In the function, self is the monster and other is the cause, where the event has one.

The events:
- 3: an enemy is seen (other: the enemy).
- 4: looking for an enemy (runs while it searches; no other).
- 5: death (no other).
- 6: change of focus, it turns on a new enemy (other: that enemy).
- 7: it is hit (other: the attacker).
- 8: it retreats (no other).
- 9: something touches it (other: what touched it).
- 10: an enemy is heard (other: the player behind the noise, if any).
- 11: end of waypoint, it reached the end of a Move (no other).
- 13: an enemy is lost from sight (other: that enemy).

Stock maps use death (5) most, then end of waypoint (11) to chain movements, enemy seen (3) and hit (7). Setting a function that does nothing is a common way to switch a handler off.
[params]
- monster: the monster whose handler to set.
- event: the event number (see the list).
- callback: the script function to run; it takes no arguments.
[returns]
Nothing.
[edge]
- Only monsters have these handlers: anything else, or an unknown object, does nothing.
- Other event numbers (0-2, 12, 14 and up) do nothing.
- The handler's flags stay as the map set them: a handler marked to run only once that has already run stays spent, whatever function is put in.
- A handler that fires while another script function is still running (set off by one of its builtins) is put off and runs later.
[example]
void MapInitialize()
{
    int ogre = Object("BridgeOgre");
    SetCallback(ogre, 5, OgreDied);
    SetCallback(ogre, 7, OgreHurt);
}

void OgreDied()
{
    UnlockDoor(Object("BridgeGate"));
    DeleteObjectTimer(self, 150);     // let the body fade
}

void OgreHurt()
{
    Attack(self, other);
}

short: Ends any fade or black screen on the host's screen at once, draws the map again and unpauses a solo game. Called Unknownc4 in older tools.
[description]
The instant way back from black. On the host's screen every running fade (to black or from black) and any lasting black screen (ImmediateBlind's, a map intro's) ends on the spot and the map is drawn again; then a paused solo game is unpaused.

Where UnBlind fades the picture back in over a short time, this cuts straight to it. This builtin had no name in the community tools (it was Unknownc4); NoX Core named it for what it does. The old name Unknownc4 still compiles. No stock map uses it.
[params]
[returns]
Nothing.
[edge]
- Only the host's own screen changes; other players see nothing.
- Fades that were waiting to run something at their end run it now (a chapter screen's fade, for instance, still sends its screen).
- The unpause only applies to a solo game.
[example]
void SkipIntro()
{
    ImmediateUnBlind();
    Frozen(GetHost(), false);
    WideScreen(false);
}

== IsSummoned
proto: int IsSummoned(int unit)
category: creatures
related: IsPet, IsOwnedBy, BecomePet, GetHost
short: Returns 1 when the monster was summoned or charmed under a player's command, otherwise 0.
[description]
Reads the monster's SUMMONED status: set on creatures a player conjures with a summoning spell and on creatures brought under command by charming them. A map's own creatures, and creatures given to a player with SetOwner, MakeFriendly or BecomePet, read 0.

Useful to treat a player's summons differently from the map's monsters in a trap or a handler. No stock map uses it.
[params]
- unit: the creature to test.
[returns]
1 for a summoned or charmed monster, otherwise 0 (also for non-monsters and unknown objects).
[edge]
- The status stays on the creature; it does not check who commands it now.
[example]
void ArenaGateTouched()
{
    if (IsSummoned(other)) {
        PushObject(other, 40.0, GetObjectX(self), GetObjectY(self));   // no summons past this gate
        return;
    }
    ObjectOn(Object("ArenaLight"));
}

== ZombieStayDown
proto: void ZombieStayDown(int zombie)
category: creatures
related: RaiseZombie, ZombieGroupStayDown, RaiseZombieGroup, Damage
short: Stops a zombie getting back up after it falls: it stays down until RaiseZombie.
[description]
Zombies (Zombie and VileZombie) don't stay dead: some time after falling, when they have an enemy, they rise again with full health. ZombieStayDown marks the monster to stay down; RaiseZombie clears the mark and raises it.

Stock maps (in chapters 4 and 6) kill set-piece zombies with Damage, keep them down with ZombieStayDown, and later raise them with RaiseZombie for an ambush.
[params]
- zombie: the zombie to keep down.
[returns]
Nothing.
[edge]
- An unknown object, or anything that isn't a monster, does nothing. Other monsters take the mark but never rise anyway.
- It can be set before the zombie falls; it takes effect whenever it lies dead.
- A burning zombie is destroyed for good whatever the mark.
[example]
void LayZombiesDown()
{
    Damage(Object("CryptZombie1"), 0, 200, 0);
    ZombieStayDown(Object("CryptZombie1"));
}

== ZombieGroupStayDown
proto: void ZombieGroupStayDown(object group)
category: creatures
related: ZombieStayDown, RaiseZombieGroup, RaiseZombie, ObjectGroup
short: ZombieStayDown for every monster in an object group: the zombies stay down until raised.
[description]
Applies ZombieStayDown to each member of an object group (a group of groups is walked too): every zombie in it stays down after falling until RaiseZombie or RaiseZombieGroup.

No stock map uses it; they call ZombieStayDown on each zombie in turn.
[params]
- group: an object group handle, from ObjectGroup("name").
[returns]
Nothing.
[edge]
- An unknown group, or a group of waypoints or walls, does nothing.
- Members that aren't monsters are skipped.
[example]
void SealCrypt()
{
    object crypt = ObjectGroup("CryptZombies");
    GroupDamage(crypt, 0, 200, 0);
    ZombieGroupStayDown(crypt);
}

== RaiseZombie
proto: void RaiseZombie(int zombie)
category: creatures
related: ZombieStayDown, RaiseZombieGroup, ZombieGroupStayDown, Attack
short: Makes a fallen zombie get up again at once, with full health, clearing its stay-down mark.
[description]
Clears the stay-down mark ZombieStayDown set and, when the monster is a zombie (Zombie or VileZombie) lying dead, raises it on the spot: it plays its get-up animation (which nothing interrupts), comes back with full health and is solid again, then carries on as a living zombie. It doesn't need an enemy in sight, unlike the zombie's own rising.

Stock maps (in chapters 4 and 6) keep set-piece zombies down with ZombieStayDown and raise them one by one with RaiseZombie when the player walks in, often with a ZombieRecognize sound.
[params]
- zombie: the dead zombie to raise.
[returns]
Nothing.
[edge]
- A zombie that is alive, an unknown object, or anything not a monster: nothing happens.
- A dead monster that isn't a zombie only loses the mark; it stays dead.
- A zombie that burned is gone for good and can't be raised.
[example]
void CryptAmbush()
{
    RaiseZombie(Object("CryptZombie1"));
    AudioEvent("ZombieRecognize", Waypoint("CryptWP"));
    FrameTimer(20, RaiseSecond);
}

void RaiseSecond()
{
    RaiseZombie(Object("CryptZombie2"));
}

== MusicPushEvent
proto: void MusicPushEvent()
category: sound
related: MusicPopEvent, Music, MusicEvent
short: Saves the music that is playing now so MusicPopEvent can go back to it later; the music itself doesn't change.
[description]
Puts the current music (its track, volume and place) on a small stack of saved tunes. The usual pattern in stock maps: MusicPushEvent, then Music to start a set piece's or a boss fight's theme, and MusicPopEvent when it is over to return to the map's music.

In a solo game this happens on the host's own client. In a network game every client is told, and each saves its own music.
[params]
[returns]
Nothing.
[edge]
- The stack holds six tunes; a seventh push is refused (nothing is saved).
- Only a push followed by Music changes what is heard.
[example]
void BossAppears()
{
    MusicPushEvent();
    Music(10, 100);              // the fight's theme
    ObjectOn(Object("BossGate"));
}

void BossDefeated()
{
    MusicPopEvent();             // back to the map's music
}

== MusicPopEvent
proto: void MusicPopEvent()
category: sound
related: MusicPushEvent, Music, MusicEvent
short: Goes back to the music saved by the last MusicPushEvent (and drops it from the saved stack).
[description]
Takes the most recently saved tune off the stack MusicPushEvent fills and plays it again. Stock maps call it when a set piece or a fight ends, often right where they unfreeze the player.

In a solo game this happens on the host's own client; in a network game every client is told.
[params]
[returns]
Nothing.
[edge]
- With nothing saved it does nothing; the current music carries on.
- Pushes and pops pair up like brackets: pop once for each push.
[example]
void ReleasePlayer()
{
    MusicPopEvent();
    Frozen(GetHost(), false);
    WideScreen(false);
}

== MusicEvent
proto: void MusicEvent()
category: sound
related: Music, MusicPushEvent, MusicPopEvent
short: Stops the music (sets it to no track).
[description]
Switches the music off, as if Music(0, 0) had been played: in a solo game on the host's own client, in a network game on every client.

No stock map uses it; stock maps change tracks with Music.
[params]
[returns]
Nothing.
[edge]
- The saved stack of MusicPushEvent is not touched, so a later MusicPopEvent still returns to the saved tune.
[example]
void EerieSilence()
{
    MusicEvent();
    AudioEvent("EarthRumbleMajor", Waypoint("CaveWP"));
}

== IsGameBall
proto: int IsGameBall(int unit)
category: objects
related: IsCrown, HasClass, GetHolder
short: Returns 1 when the object is a GameBall (the ball of the network Flagball game), otherwise 0.
[description]
Compares the object's type with GameBall, the ball the network Flagball game is played with. Useful in a handler that many things can set off, to react only to the ball (a goal plate, a pit that returns the ball).

No stock map uses it.
[params]

{

            MoveObject(other, GetWaypointX(Waypoint("BallStartWP")), GetWaypointY(Waypoint("BallStartWP")));
    }
}

== EndGame
proto: void EndGame(int ending)
category: game
related: ImmediateBlind, DeathScreen, StartupScreen, WideScreen
short: Ends a solo campaign on the host's screen: 0 Warrior, 1 Wizard, 2 Conjurer. Records the class as finished, plays its ending movie and the credits, then leaves the game.
[description]
The very end of a campaign. The last map of each campaign calls it once its final scene is over: EndGame(0) in the warrior's, EndGame(1) in the wizard's and EndGame(2) in the conjurer's.

On the host's client it marks that class's campaign as completed in the game's settings (nox.cfg), blacks out the screen over everything, unpauses, brings the HUD back and leaves the game. The class's ending movie (Warrior, Wizard or Conjurer) plays, then the credits roll, and the player ends up at the main menu.

NoX Core's client plays the movie and the credits before leaving the game instead of from the main menu, and saves the completed mark at once (vanilla deviations); what the player sees is the same.
[params]
- ending: whose ending: 0 Warrior, 1 Wizard, 2 Conjurer.
[returns]
Nothing.
[edge]
- Only the host's own client is affected; with no host client (a dedicated server) nothing happens.
- Any other number plays no movie, only the credits, and marks some other bit in the settings.
- After a widescreen scene the HUD windows a past WideScreen hid can come back open (OB-144).
[example]
void FinalSceneOver()
{
    WideScreen(false);
    EndGame(2);          // the conjurer's ending
}

== ImmediateBlind
proto: void ImmediateBlind()
category: game
related: ImmediateUnBlind, Blind, UnBlind, WideScreen
short: Turns the host's screen black at once, over everything including the HUD, until UnBlind or ImmediateUnBlind.
[description]
The instant cut to black. Any fade running on the host's screen ends, the map stops being drawn and a black screen covers everything, the HUD included. It lasts until UnBlind fades the picture back in or ImmediateUnBlind brings it back at once.

Blind does the same with a fade over 25 frames and leaves the HUD visible; use ImmediateBlind when the change must be hidden at once. The game is not paused: the script goes on, so scenery can be moved and creatures placed behind the black. Wiz11A uses it the moment its final enemy falls, freezing everyone behind the black before the closing scene.
[params]
[returns]
Nothing.
[edge]
- Only the host's own screen goes black; other players see nothing.
- While UnBlind's fade-in is running no black screen is added (the map still stops being drawn).
[example]
void CutToThroneRoom()
{
    ImmediateBlind();
    Frozen(GetHost(), true);
    MoveObject(GetHost(), GetWaypointX(Waypoint("ThroneWP")), GetWaypointY(Waypoint("ThroneWP")));
    SecondTimer(1, RevealThroneRoom);
}

void RevealThroneRoom()
{
    UnBlind();
    Frozen(GetHost(), false);
}

== ChangeScore
proto: void ChangeScore(int player, int amount)
category: players
related: GetScore, GetGold, ChangeGold
short: Adds an amount (negative to take away) to a player's score and to its team's, and tells every player.
[description]
Changes the score a player has in a scored network game (the kills counted in the scoreboard) by the given amount, and the score of the player's team, if it is on one, by the same amount. Every client is told the new numbers.

The game checks the score limit every frame, so a score raised to the limit wins the game as if it had been earned. A map can use it for its own scoring: points for a goal, a capture or a race.

No stock map uses it.
[params]
- player: the player whose score changes.
- amount: how much to add; a negative amount takes points away.
[returns]
Nothing.
[edge]
- Anything that isn't a player, or an unknown object, does nothing.
- The score can go below zero.
- Only the numbers change: no kill message or sound.
[example]
void GoalScored()
{
    int scorer = GetCaller();
    if (scorer != 0) {
        ChangeScore(scorer, 5);
        PrintToAll("Con02a:ObjectiveComplete");
    }
}

== GetScore
proto: int GetScore(int player)
category: players
related: ChangeScore, GetGold
short: Returns a player's score (its kills or points in a scored game), or 0 for anything that isn't a player.
[description]
Reads the player's current score, the number the scoreboard shows: kills in a deathmatch, points given by ChangeScore.

No stock map uses it.
[params]
- player: the player to ask about.
[returns]
The player's score (it can be negative), or 0 for a non-player or an unknown object.
[edge]
- It reads the player's own score, not its team's.
[example]
void PrizeChestOpened()
{
    if (GetScore(other) >= 10)
        UnlockDoor(Object("PrizeVault"));
    else
        Print("Con02a:BeginMission");
}
